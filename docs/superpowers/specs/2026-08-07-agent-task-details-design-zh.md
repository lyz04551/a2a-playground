# Agent 任务详情设计

## 目标

让右侧 Run 轨迹中的每个 Agent 任务都可以点击，用户能够查看由哪个 Agent 执行、Host 分配了什么任务、依赖关系、执行状态、重试记录和返回结果。

## 交互

- Agent 行使用支持键盘操作的按钮。
- 点击后在当前工作区打开 Ant Design 抽屉，不跳转页面。
- 当前选中的任务有清晰高亮。
- 抽屉展示 Agent 身份、任务目标、原始输入、状态、耗时、依赖任务、完成标准、尝试与替换记录、执行结果，以及失败、阻塞或审批原因。
- 没有结果时根据任务状态显示明确说明，不再只显示 `—`。
- 同一依赖层级的任务标记为并行；依赖任务显示前置任务名称。
- Host 最终综合回复仍保留在主对话区。

## 数据流

`host.plan_created` 提供任务目标、输入、依赖、完成标准和 Agent ID。后续生命周期事件更新尝试次数、替换 Agent、状态、时间和结果。`adaptRunStateForLegacy` 将规范化数据传给现有轨迹组件。缺少计划元数据的旧 Run 仍可点击，并展示当前可获得的信息。

## 安全与残留 Run

抽屉明确区分执行中、已完成、失败、阻塞、等待审批和已取消状态，并显示最近事件时间，避免把数据库中的残留 `running` 状态误认为仍在真实执行。界面不会自动取消 Run。

## 测试

- Reducer 测试验证计划元数据和任务结果不会在规范化时丢失。
- 纯视图模型测试验证状态文案、无结果提示、依赖名称、Agent 替换记录和旧数据回退。
- 前端生产构建验证抽屉集成。

## 验收标准

- 点击任意 Agent 任务可以打开详情。
- Ops 与 Security 任务显示各自不同的目标和结果。
- 依赖型综合任务显示两个前置任务。
- 已完成任务展示完整 Agent 输出。
- 失败、阻塞、审批、取消和无结果状态均有明确说明。
- 支持键盘打开和关闭。
