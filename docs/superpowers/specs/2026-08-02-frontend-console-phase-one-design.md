# A2A Playground 前端控制台第一阶段设计

## 目标

将现有 A2A Playground 升级为面向内部研发与运维人员的专业控制台，同时保留适合产品演示的视觉完成度。第一阶段聚焦全站统一、核心操作效率和现有运行数据的可视化，不伪造后端暂未提供的数据。

## 产品定位与视觉方向

采用“专业控制台”方向：深蓝灰作为结构色，青绿色作为主要操作色；蓝色表示编排过程，橙色表示待审批，红色表示故障。默认提供亮色主题，同时实现完整暗色主题。

全站统一字体层级、间距、圆角、阴影、按钮、卡片和状态标签。动效仅用于页面进入、状态变化与任务执行反馈。页面主体文案统一为中文，Agent、Task、Tool、SSE 等工程术语保留英文。

## 信息架构

主导航包含：

- Dashboard：系统概览、在线 Agent、近期任务、待审批事项和快捷 Prompt。
- Workspace：会话、消息、运行轨迹及调试信息。
- Agents：Agent 注册、在线状态、能力和管理操作。
- Events：运行事件统计、筛选、诊断与审计。

左侧导航支持折叠。顶部区域提供当前页面信息、全局命令入口、主题切换、通知入口和设置。桌面端优先保证信息效率；平板隐藏次要面板；手机端通过抽屉访问导航、会话和执行轨迹。

## 第一阶段功能

### Dashboard

Dashboard 复用现有接口展示系统与模型配置状态、在线 Agent 数、近期任务、待审批事项和快捷 Prompt。没有数据时展示有操作指引的空状态，不展示推测或随机统计。

### 全局搜索与命令面板

使用 `Command+K` 或 `Ctrl+K` 打开命令面板，可搜索和跳转页面、Agent、会话及已加载事件，并支持新建会话等安全的快捷操作。第一阶段只检索前端已获取的数据，不新增后端全文检索服务。

### Workspace

桌面端保持会话、对话、执行轨迹三栏结构：

- 会话区支持搜索、重命名、删除和新建。
- 消息支持复制；发送区提供 Kubernetes 运维相关快捷 Prompt。
- 执行过程以 Host → Agent → Tool → Result 时间线呈现，突出当前步骤、耗时、等待审批与失败节点。
- 调试抽屉展示已有 SSE 事件、请求信息、Task ID、耗时和可复制的原始 JSON。
- Token 信息仅在服务端真实返回时展示，否则明确标记为暂无数据。

### Agents

统一 Agent 卡片与状态表达，展示现有在线状态、能力标签、地址和管理操作。延迟、成功率、最近调用及异常原因留待后续服务端接口完善后接入，第一阶段不使用假数据。

### Events

保留并统一现有统计、搜索和筛选能力，增加事件详情抽屉及复制原始 JSON。失败、执行中、完成和等待审批状态采用全站一致的语义颜色。

### 设置与本地偏好

提供亮色/暗色主题、紧凑模式、侧栏折叠和中英文切换。主题、密度、语言、侧栏状态及首次引导完成状态保存在 `localStorage`；Agent、会话、事件等业务数据继续以服务端为准。

### 首次引导与反馈状态

根据 Agent 注册、模型配置和会话状态展示分步引导，允许跳过。全站补齐加载、空数据、错误和重试状态。API 失败时尽量保留已加载内容；SSE 中断时保留已完成步骤，并明确显示中断位置与重试入口。

## 组件与状态边界

- 全局布局负责导航、顶部工具区、响应式抽屉和页面容器。
- 设计变量负责主题色、语义色、间距、圆角、阴影和密度切换。
- 设置状态负责读取、校验并持久化本地偏好。
- 命令面板通过明确的数据适配接口汇总页面、Agent、会话和事件命令。
- Workspace 保持现有流式运行 Hook 为业务数据源，展示组件不直接操作网络请求。
- 运行时间线和调试抽屉消费统一后的运行事件，避免各自解析 SSE。

保留 React、Vite、Ant Design 和现有 API，不进行框架迁移。逐步将页面内联样式迁移到统一样式与组件层，但不做与本阶段无关的重构。

## 无障碍与响应式

命令面板、抽屉、导航和主要操作必须支持键盘访问、可见焦点和必要的 ARIA 标签。桌面端使用高效多栏布局；平板将执行轨迹放入抽屉；手机端将导航、会话及轨迹均放入抽屉，并保证输入区始终可用。

## 测试与验收

- 为设置持久化、命令搜索、会话操作和执行轨迹状态补充单元测试。
- 运行现有前端测试，确保流式事件与 Workspace 状态逻辑不回归。
- 运行生产构建，检查静态资源和 CSS 无错误。
- 检查亮色、暗色、紧凑模式及桌面/平板/手机关键宽度。
- 验证键盘打开与关闭命令面板、焦点回退、消息复制、事件 JSON 复制和 SSE 中断状态。

## 明确不在第一阶段的范围

以下功能需要新的持久化字段或后端统计接口，放入后续阶段：会话置顶与收藏、编辑后重发、重新生成、Token 与成本统计、Agent 成功率和调用趋势、任务节点级重试、完整通知持久化及历史数据分析。

## 实施约束

当前工作区存在未提交改动。实施时只修改第一阶段直接相关文件，保留并兼容现有工作，不覆盖或回滚用户改动。每一组变更都应可独立验证。
