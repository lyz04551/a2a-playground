# Markdown 长内容布局修复设计

## 目标

修复 Agent 消息中的 Pod 名、镜像地址、URL、IP 和错误信息等长行内代码撑宽消息卡片、随后被横向裁切的问题。保证完整内容可读，同时不改变普通文本、代码块和表格的既有交互。

## 根因

`MarkdownContent` 的父容器虽然声明了换行，但行内 `code` 没有自己的宽度和断行约束。长行内代码形成过大的最小内容宽度；消息正文又使用 `overflow-x: hidden`，因此超出部分被裁掉。

## 方案

采用局部 CSS 修复，不修改 Markdown 数据或插入软换行：

- 消息卡片、正文和 Markdown 内容节点设置 `min-width: 0` 与 `max-width: 100%`，使其可以在 Grid/Flex 布局中收缩。
- 行内 `code` 使用 `white-space: normal`、`overflow-wrap: anywhere` 和 `word-break: break-word`，允许长标识符在可用宽度内换行。
- `pre code` 恢复代码块语义，不继承行内代码的强制换行；代码块继续通过自身横向滚动查看原始格式。
- 表格继续放在已有的横向滚动容器内，不改变列宽行为。

不采用 JavaScript 拆词或在输出文本中插入零宽字符，因为这会污染复制内容，并把展示问题扩散到数据层。

## 验证

- 先增加 CSS 回归测试，证明当前行内代码缺少断行约束。
- 修改样式后运行前端完整测试和生产构建。
- 使用包含长 Pod 名、私有镜像地址和网络错误的 Markdown 样例进行浏览器视觉检查，确认消息卡片不产生页面级横向溢出，完整文本可见，代码块仍可横向滚动。

## 范围边界

仅修复聊天消息与共享 `MarkdownContent` 的长内容布局；不调整字体、卡片尺寸、后端总结格式或 Agent 输出内容。
