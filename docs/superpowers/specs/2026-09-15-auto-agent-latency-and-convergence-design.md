# Auto 子 Agent 延迟与收敛优化设计

## 背景

真实页面测试中，Auto Run 第一轮耗时约 182 秒。Kubernetes 工具通常在
0.05～2 秒内返回，但最后一次工具结果到子 Agent 报告耗时约 73 秒。Host
决策仅耗时约 3～6 秒。第一轮的部分结果又被 Host 判定为不足，触发近似任务
进入第二轮。

## 根因

1. A2A 远端上下文当前按 `conversation_id + agent_id` 复用。同一会话中相互
   独立的 Host 任务因此共享 LangGraph checkpoint，累积旧工具调用、旧工具
   结果和旧报告。
2. 子 Agent 达到调查超时后，会再使用最多 40,000 字符证据调用一次最长
   35 秒的强制总结，导致单轮耗时稳定接近 180 秒。
3. Host 将所有 `partial` 结果无条件评为 `insufficient`。模型可通过改写任务
   描述绕过精确 fingerprint 防重，重新执行整套审计。
4. 页面只收到工具事件和最终完整消息，模型处理上下文与总结期间缺少阶段状态。

## 目标

- 独立 Host 任务拥有独立的子 Agent checkpoint。
- 审批恢复和明确的逻辑 continuation 仍复用原 checkpoint。
- 部分结果包含可用证据时，Host 能收敛并综合回答；补证不能重跑完整审计。
- 最终总结只接收本轮、去重、受限的证据。
- 页面能区分调查与总结阶段。
- 常规只读诊断在一轮完成，必要时最多执行一轮针对性补证。

## 设计

### 任务上下文隔离

Gateway 为普通委派生成包含逻辑任务 ID 的 context ID，并为该逻辑任务保存
binding。只有审批决定或显式 continuation 才复用已有 context。不同 Host 轮次、
不同逻辑任务不得共享 checkpoint。

### 有界证据总结

Runtime 维护本次 `stream()` 已观察到的工具结果。超时总结仅使用本次结果，按
调用 ID 去重，并设置更小的总字符上限和单项上限。强制总结与调查共用总运行
期限，不能在调查超时后无条件追加完整的 35 秒等待。

### Host 收敛

`partial` 不再自动等同于失败。若结果包含非空摘要或证据，Host 将其保存为可
综合结果。Host 只允许一轮补证，且补证任务必须引用一个明确缺口；已经部分完成
的宽泛审计不得再次委派。达到补证上限后，Host 使用现有证据完成回答，并披露
限制。

### 可观察性

子 Agent 在进入最终生成或强制总结时发出 `summarizing` 状态。事件中记录本次
工具调用数、总结证据字符数和阶段耗时；不记录敏感工具内容。

## 错误处理

- 子 Agent 总结超时：立即返回确定性部分报告，不再次调用模型。
- 部分结果无任何摘要或证据：Host 可执行一次针对性恢复或报告失败。
- 达到任务或轮次预算：Host 必须综合已有结果，不能以预算耗尽作为正常诊断的
  最终失败原因。

## 测试

- Gateway 测试验证两个独立逻辑任务获得不同 context，审批恢复复用原 context。
- Runtime 测试验证强制总结仅包含本轮、去重、受限证据。
- Host 测试验证有内容的 partial 可以进入综合，且相同目标不会重复委派。
- 事件测试验证总结阶段状态和耗时元数据。
- 端到端页面测试再次运行“检查集群有什么问题”，记录首轮和总耗时，并确认不再
  出现六轮近似任务。

## 非目标

- 本次不更换 Qwen 模型或修改 vLLM 部署参数。
- 本次不处理浏览器主动取消向远端 A2A task 的传播。
- 本次不改变 Kubernetes 工具本身的行为。
