# 模型与 MCP 连接诊断设计

## 目标

在现有“模型设置”页面增加一个紧凑的“连接诊断”区域，让用户能主动验证 Host DeepSeek、子 Agent 本地 Qwen 以及各 Agent 使用的 MCP Server 是否真正可用，并快速区分模型、Agent 传输和 MCP 三类故障。

## 用户界面

连接诊断使用左侧导航中位于“模型设置”之后的独立“连接测试”页面，并拆成三张互不嵌套的卡片。模型设置页保持纯配置用途：

- Host 模型测试：独立按钮测试 DeepSeek 真实推理状态与耗时。
- 本地大模型测试：独立按钮测试每个已注册子 Agent 的 Qwen 推理状态与耗时。
- MCP Server 测试：独立按钮测试每个 Agent 的 MCP `list_tools`、工具数量与耗时。

不提供“全部测试”按钮。三张卡片拥有独立 loading、结果和错误状态；点击其中一张不会触发另外两类探测。状态分为未测试、测试中、正常、异常。错误信息经过长度限制和敏感字段过滤。页面打开时不自动探测，避免产生不必要的模型调用。

## 探测语义

### Host DeepSeek

后端使用当前生效的 Host 模型配置发送一个低 token、无工具的确定性请求，要求仅返回 `OK`。只有实际收到非空模型响应才算成功；“配置存在”不算成功。设置独立超时并返回模型名、耗时和脱敏错误。

### 子 Agent Qwen

共享 Agent Runtime 暴露只读诊断端点。端点直接调用已配置模型，不进入 ReAct 图、不挂载工具、不创建 A2A Task，也不写入会话或 checkpoint。每个 Agent 独立返回模型探测状态与耗时，因此能识别单个 Agent 的配置差异。

### MCP Server

同一诊断端点使用 Agent 自己的 MCP 配置重新执行 `list_tools`。返回成功状态、工具数量、耗时和脱敏错误；不调用任何具体 Kubernetes 工具，因此不会读取资源或改变集群。

## 后端数据流

前端调用同一诊断 API，但显式传入 `host`、`models` 或 `mcp` 探测目标。Backend 只执行所选类别：

1. `host` 只执行 Host 模型探测。
2. `models` 获取已注册 Agent，并行调用各 Agent 的无工具模型探测。
3. `mcp` 获取已注册 Agent，并行调用各 Agent 的 MCP 工具发现探测。
3. 为第三方或旧版 Agent 保留兼容降级：若没有诊断端点，返回“不支持”，而不是将其误报为离线。

聚合 API 返回稳定的结构化结果，不暴露 API Key、完整模型响应、内部请求头或 MCP 参数。

## 可靠性与安全

- 所有探测均为显式点击触发且只读。
- 每个远程步骤设置短超时；单个 Agent 超时不阻塞其他结果。
- Host 与子 Agent 模型探测限制输出 token，并关闭 Qwen 隐藏 thinking，避免诊断本身变慢。
- MCP 只执行工具发现，不执行工具。
- 每张卡片在自己的请求进行中禁用重复提交，但不阻塞其他类别的按钮。

## 测试与验收

- 单元测试覆盖成功、模型失败、MCP 失败、Agent 不支持诊断端点和超时。
- API 测试确认聚合结果互不阻塞且不包含敏感配置。
- 前端测试覆盖状态映射和结果展示。
- 浏览器分别点击三种测试，确认每张卡片仅展示对应结果，失败项具有可读错误且页面保持响应。

## 范围边界

本功能不测试模型回答质量，不调用 Kubernetes 资源工具，不执行写操作，不修改模型配置，也不替代已有的持续健康监控。
